# Functional requirements

Functional requirements of the module, split by platform. The "Previous ID" column keeps the identifier they had in the per-platform specification.

## Web

| ID | Requirement | Acceptance criterion | Use case | Previous ID |
|---|---|---|---|---|
| `RF-WEB-ADM-01` | View the dashboard and management modules. | Shows totals of wines, wineries, events, routes, reviews and users, plus active users, published events and published routes; the users total, user management and notifications are ADMIN only. | [`UC-ADM-01`](use-cases/uc-adm-01-dashboard.md) | `RF-WEB-ADMIN-001` |
| `RF-WEB-ADM-02` | Access administrative queues and counts. | ADMIN/MODERATOR sees pending publications and reports by status, pagination and detail; errors are not represented as zero pending. | [`UC-ADM-01`](use-cases/uc-adm-01-dashboard.md) | `RF-WEB-SAFETY-005` |
| `RF-WEB-ADM-03` | Search, page and select management resources. | Each module retains list, search, page and selection; it fetches detail by ID before editing rather than treating an incomplete summary as detail. | [`UC-ADM-02`](use-cases/uc-adm-02-manage-wines.md) | `RF-WEB-ADMIN-002` |
| `RF-WEB-ADM-04` | Create or edit catalogue wines. | Manages exposed identity, winery, type, vintage, grapes, ES/EN descriptions, alcohol, prices, temperature, image and sensory scores. | [`UC-ADM-02`](use-cases/uc-adm-02-manage-wines.md) | `RF-WEB-ADMIN-003` |
| `RF-WEB-ADM-05` | Activate/deactivate and feature wines. | Editing retains isActive/isFeatured flags; inactive wines leave the ordinary catalogue and featuring does not guarantee first place in highlights. | [`UC-ADM-02`](use-cases/uc-adm-02-manage-wines.md) | `RF-WEB-ADMIN-004` |
| `RF-WEB-ADM-06` | Retain omitted data and explicitly clear fields. | clearFields identifies intentional empties; zero, false and empty arrays are retained and coordinates are cleared as a pair. | [`UC-ADM-02`](use-cases/uc-adm-02-manage-wines.md) | `RF-WEB-ADMIN-012` |
| `RF-WEB-ADM-07` | Confirm destructive change results. | Only ADMIN deletes, with confirmation and with identity confirmed in the last five minutes; failure retains the resource without presenting success or falsely completing the operation. | [`UC-ADM-02`](use-cases/uc-adm-02-manage-wines.md) | `RF-WEB-ADMIN-013` |
| `RF-WEB-ADM-08` | Refresh affected views after saving. | Only success invalidates related lists/details/statistics; late responses cannot change a closed editor or another selection. | [`UC-ADM-02`](use-cases/uc-adm-02-manage-wines.md) | `RF-WEB-ADMIN-014` |
| `RF-WEB-ADM-09` | Manage wineries. | Creation/editing relates country/region and available identity, description, image, contact, address/coordinates. | [`UC-ADM-03`](use-cases/uc-adm-03-manage-wineries.md) | `RF-WEB-ADMIN-005` |
| `RF-WEB-ADM-10` | Manage events and registration. | Creation/editing includes dates, location, organizer, price/capacity, contact, cover and settings: currency, deadline, maximum, approval, confirmation and hold. | [`UC-ADM-04`](use-cases/uc-adm-04-manage-events.md) | `RF-WEB-ADMIN-006` |
| `RF-WEB-ADM-11` | Apply permitted event transitions. | The editor offers draft, published, cancelled and completed; the API applies the allowed transitions (a cancelled event never changes again, a completed one cannot be cancelled or postponed) and “sold out” is set by the system from capacity. An invalid transition is rejected with 400. | [`UC-ADM-04`](use-cases/uc-adm-04-manage-events.md) | `RF-WEB-ADMIN-007` |
| `RF-WEB-ADM-12` | Retain history when deleting/cancelling an event. | The administrative action displayed as delete cancels the aggregate and its active registrations; it does not physically delete the row. The cancel dialog offers a reason select with "Unforeseen circumstances" preselected (an optional note of up to 280 characters appears only for "Other reason"), so confirming never requires typing; the reason is sent as the `DELETE /admin/events/{id}` body and active attendees receive it by email. | [`UC-ADM-04`](use-cases/uc-adm-04-manage-events.md) | `RF-WEB-ADMIN-008` |
| `RF-WEB-ADM-13` | Manage routes and covers. | Creation/editing includes origin, subregion, description, distance, duration/days, length and exposed image/wine-type fields. | [`UC-ADM-05`](use-cases/uc-adm-05-manage-routes.md) | `RF-WEB-ADMIN-009` |
| `RF-WEB-ADM-14` | Edit route stops. | Supports adding, editing, removing and ordering; linking a winery does not let geocoding a draft change that winery on cancellation. | [`UC-ADM-05`](use-cases/uc-adm-05-manage-routes.md) | `RF-WEB-ADMIN-010` |
| `RF-WEB-ADM-15` | Distinguish route draft, publication and archive. | An empty DRAFT can be saved; publishing requires at least one stop with a name and valid coordinates, and states respect DRAFT/PUBLISHED/ARCHIVED. | [`UC-ADM-05`](use-cases/uc-adm-05-manage-routes.md) | `RF-WEB-ADMIN-011` |
| `RF-WEB-ADM-16` | Read the submission queue and details. | Lists by state/text and page; detail includes data, available image and previous decisions without anonymous exposure. | [`UC-ADM-06`](use-cases/uc-adm-06-review-wine-submissions.md) | `RF-WEB-SUBADMIN-001` |
| `RF-WEB-ADM-17` | Preview a submission image with authorization. | Missing, loading and failure states are separate; image retry retains decision/reason and does not display another selection's image. | [`UC-ADM-06`](use-cases/uc-adm-06-review-wine-submissions.md) | `RF-WEB-SUBADMIN-002` |
| `RF-WEB-ADM-18` | Approve a new wine with corrections. | APPROVE_NEW supports exposed overrides and applies server deduplication/rules; catalogue is not created from the queue summary alone. | [`UC-ADM-06`](use-cases/uc-adm-06-review-wine-submissions.md) | `RF-WEB-SUBADMIN-003` |
| `RF-WEB-ADM-19` | Merge, reject or request corrections. | MERGE_EXISTING requires a target wine; REJECT and REQUEST_CORRECTIONS record a reason; UI requires notes before deciding. | [`UC-ADM-06`](use-cases/uc-adm-06-review-wine-submissions.md) | `RF-WEB-SUBADMIN-004` |
| `RF-WEB-ADM-20` | Record the outcome and update projections. | Server sets decision, actor and date; success updates queue/catalogue/statistics and failure does not falsely complete review. | [`UC-ADM-06`](use-cases/uc-adm-06-review-wine-submissions.md) | `RF-WEB-SUBADMIN-005` |
| `RF-WEB-ADM-21` | Review reports and remove content. | OPEN moves to IN_REVIEW and is assigned; closing as RESOLVED/DISMISSED requires an explanation and closed cases never reopen. On reviews and comments the content can be removed with confirmation, which resolves the report. | [`UC-ADM-07`](use-cases/uc-adm-07-moderate-reports.md) | `RF-WEB-SAFETY-006` |
| `RF-WEB-ADM-22` | Respect assignment and conflicts of interest. | Reporter or author cannot resolve their own case; another moderator cannot take an assigned review. | [`UC-ADM-07`](use-cases/uc-adm-07-moderate-reports.md) | `RF-WEB-SAFETY-007` |
| `RF-WEB-ADM-23` | Review pending publications. | The queue holds earlier pending items and unapproved edits; approving or rejecting applies to the revision that was seen. Rejecting asks for a one-tap preset reason (offensive preselected) and the note only appears with Other. | [`UC-ADM-08`](use-cases/uc-adm-08-review-publications.md) | `RF-WEB-SAFETY-008` |
| `RF-WEB-ADM-24` | Read and remove reviews administratively. | Administrators and moderators list, open the details and delete by ID with confirmation; this does not replace report review or author editing. | [`UC-ADM-09`](use-cases/uc-adm-09-manage-reviews.md) | `RF-WEB-USERS-007` |
| `RF-WEB-ADM-25` | Read users and their status. | Searches/pages and shows authorized identity, roles, verification, active/inactive/suspended status and detail data. | [`UC-ADM-10`](use-cases/uc-adm-10-manage-users.md) | `RF-WEB-USERS-001` |
| `RF-WEB-ADM-26` | Replace a role through the selector. | Saving sets USER plus the selected USER/MODERATOR/PARTNER/ADMIN role; repeated selection does not accumulate roles. | [`UC-ADM-10`](use-cases/uc-adm-10-manage-users.md) | `RF-WEB-USERS-002` |
| `RF-WEB-ADM-27` | Protect administrative continuity. | Cannot remove one's own administrative access or disable the last active/unsuspended admin; knowing an endpoint does not bypass protection. | [`UC-ADM-10`](use-cases/uc-adm-10-manage-users.md) | `RF-WEB-USERS-003` |
| `RF-WEB-ADM-28` | Delete users with confirmation and protection. | Only ADMIN uses administrative deletion; server processes relations and protected accounts cannot be deleted. | [`UC-ADM-10`](use-cases/uc-adm-10-manage-users.md) | `RF-WEB-USERS-005` |
| `RF-WEB-ADM-29` | Reauthenticate the administrator for sensitive actions. | REAUTHENTICATION_REQUIRED opens the confirmation with the password, or with Google or Apple if the account uses them, renews the five-minute proof and retries once; cancelling does not run the action. | [`UC-ADM-10`](use-cases/uc-adm-10-manage-users.md) | `RF-WEB-USERS-006` |
| `RF-WEB-ADM-30` | Suspend and reactivate an account. | Suspending asks for a preset reason (one-tap chips, spam preselected; a detail only under Other) and restricts later access; the person is emailed the reason; reactivating reverses the suspension, distinct from personal user blocking. | [`UC-ADM-11`](use-cases/uc-adm-11-suspend-user.md) | `RF-WEB-USERS-004` |
| `RF-WEB-ADM-31` | Send announcements. | ADMIN only: one-tap news or service notice, per-language title and formatted body, channels and segment with live reach, backend email and push preview, test to oneself, send only after confirming the number of accounts per channel, and a history of the latest 20 sends with their results per channel (emails sent and failed, push accounts reached, failures and opens) and a detail per send. A retry of the same draft never sends twice. | [`UC-ADM-12`](use-cases/uc-adm-12-send-announcements.md) | `RF-WEB-USERS-008` |
| `RF-WEB-ADM-32` | Control pushes by type. | ADMIN only: one switch per push type (turning off a transactional one asks for confirmation) with the latest changes, results for 1, 7 or 30 days, the “Engagement” panel (sent, opened, open rate, opt-outs and paused per engagement type) and the read-only provider. | [`UC-ADM-13`](use-cases/uc-adm-13-control-push.md) | `RF-WEB-USERS-009` |
| `RF-WEB-ADM-33` | Require a minimum app version per platform. | ADMIN only: for iOS and Android, the current minimum with who changed it and when, the latest 20 changes and the warning to raise it only after the store has published that build; validates `major.minor.patch` before sending, raising it asks for confirmation, removing it leaves the platform with no minimum and every change asks to confirm the identity. | [`UC-ADM-15`](use-cases/uc-adm-15-minimum-app-version.md) | — |
| `RF-WEB-ADM-34` | Decide catalog quality reports. | A report with reason `CATALOG_QUALITY` shows "Vinnot (automatic)" as the reporter, the matched wine, the wine the member chose, the localized explanation and links to both wines; it can be taken, resolved or dismissed with a decision but never removes the wine. | [`UC-ADM-07`](use-cases/uc-adm-07-moderate-reports.md) | — |
