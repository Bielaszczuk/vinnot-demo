# Testing

Test cases of the module: one for the main flow of each use case and one for each alternative flow. They can be run by hand; the automated tests column shows which tests exercise the use case.

## Test cases

| ID | Use case | Steps | Expected result |
|---|---|---|---|
| `CP-GAM-01` | [`UC-GAM-01`](use-cases/uc-gam-01-earn-and-lose-points.md) | 1) The person does something that earns points, such as publishing an approved review. 2) The owning module's use case (reviews, cellar, wines, events or users) calls its points port; its `Gamification*PointsAdapter` turns it into an `AwardPointsCommand` with the source and source key. 3) `AwardPointsCommandHandler` locks the person's points account. 4) If an active award with the same person, source and key already exists, it ends without changes. 5) `PointSource.grant` computes the points: first the source's daily limit, then the global cap of 40, with the day in the person's time zone. 6) It stores the award and the movement and updates points and tier. 7) If the person reached a higher tier for the first time, it queues the `TIER_REACHED` notice ([`UC-GAM-03`](use-cases/uc-gam-03-celebrate-tier.md)). | The person earns the action's points, within the limits. |
